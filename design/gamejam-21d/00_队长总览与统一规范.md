# 《林间无声》21天 Game Jam 制作包

版本：v1.0｜日期：2026-09-21｜项目名、角色名均为工作名，可以替换。

## 1. 本次到底做什么

制作一款俯视斜角、双角色切换的实时潜行战术游戏。玩家利用视野死角、灌木、声音和两名角色的互补技能，穿过森林岗哨，取得巡防文书并一起撤离。

**21天交付目标：一个首次游玩约10—15分钟的完整教学关；包含开始、教学、潜行解题、失败重试、胜利结算。** 核心体验是“观察—引开—处理—藏匿—配合”，不是正面战斗。

默认制作条件：PC单机、键鼠、1名程序主力，各美术方向有人负责但可能兼职；引擎未定，全部逻辑使用引擎无关表述。关卡尺寸、帧率和资源预算都是本项目起始建议，需在实际设备上调整。没有把这些建议说成《影子战术》的原作数据。

## 3. 冻结的范围

| 等级 | 含义 | 内容 |
|---|---|---|
| P0 | 没有就不能称为本次完整原型 | 双角色切换；点击寻路；行走/下蹲/奔跑；视野与听觉；普通守卫巡逻与调查；近身暗杀；投石；可回收飞镖；笛声；可回收陷阱；尸体拖拽与灌木藏尸；目标交互；检查点重试；首关；基础UI和必要反馈 |
| P1 | P0闭环稳定以后再加 | 暂停规划并同时执行一条技能指令；指定点跳跃；额外环境氛围；视野固定显示优化 |
| P2 | 本届不排正式制作 | 自由跳跃/攀爬/钩锁/游泳；复杂高低差；非致命击晕与唤醒；武士/精英敌人；正面战斗与血量；任意时刻存档；多关卡；动态昼夜；联网；全剧情配音 |

P1必须可以整体关闭，不影响首关通关。尤其不能把结尾设计成“没有同步模式就过不去”。

## 4. 双角色与统一识别

借鉴友希的“陷阱+诱敌”和隼人的“近身潜入+投掷”定位，角色采用本项目自己的名字、服装轮廓和道具设计。机制参考关系在这里说明，所有生产文件使用下面的ID。

| 项目 | CHR_A：苇音 | CHR_B：岚刃 |
|---|---|---|
| 定位 | 轻巧的林地设陷者；对应友希型玩法 | 干练的潜入者；对应隼人型玩法 |
| 轮廓 | 短外套、侧腰圆形陷阱包、侧束短发；头部轮廓偏圆 | 收束长衣、右肩不对称护肩、腰侧短刀；轮廓偏三角 |
| 主色/识别色 | 棕褐衣料、苔绿辅色、琥珀黄识别色 #D6A34A | 靛蓝衣料、灰褐辅色、青蓝识别色 #55A8BB |
| 专属道具 | 短竹笛、折叠夹式机关、短匕首 | 短刀、小石子、三叶飞镖 |
| 专属技能ID | SK_A_TRAP、SK_A_FLUTE | SK_B_STONE、SK_B_DART |
| 共通技能ID | SK_COMMON_KILL；拖拽、藏尸、拾取为情境交互 | 同左 |
| 头像要求 | 与3D一致的发型、领口、陷阱包肩带；琥珀色框 | 与3D一致的护肩、领口、刀柄；青蓝色框 |
| 地面标识 | 圆环+小圆点+编号1 | 圆环+小三角+编号2 |

两人均为成年角色。身份表现靠轮廓与道具，不依赖脸部细节。原型可共享一个人形骨架；身高通过模型比例轻微调整，不做两套完全独立骨架。

**固定键位：1苇音、2岚刃。首关岚刃先出场，苇音在C区解锁。** 游戏初始默认选中岚刃；苇音头像显示锁定和“前往会合点”。

## 5. 风格与场景语言

方向：风格化半写实、自然材质、大块明暗、适当夸张轮廓；俯视镜头下仍能分辨人物动作、掩体边缘和可行走区域。场景设为山林旧驿道、荒废井亭和临时岗哨，时间为薄雾清晨。

| 视觉层级 | 执行规则 |
|---|---|
| 地表 | 低饱和土褐与灰绿；道路比背景更浅、更少碎纹理 |
| 自然物 | 树冠按块组织、树皮与岩石有体积，避免照片噪点堆满屏幕 |
| 角色与敌人 | 角色识别色集中在上半身；敌人深褐灰布衣+暗红腰带 |
| 交互物 | 文书箱用温暖浅木色和细微描边；井、岩石仅作掩体时不闪光 |
| 功能颜色 | 青白=范围预览；黄=怀疑；红=确认发现/危险；绿色不承担唯一安全提示 |
| 材质 | 共享木、石、布、金属材质；泥土和布高粗糙度，刃口仅少量高光 |
| 屏幕信息 | 声波、视锥、选中环的辨识度高于花草装饰；树冠可以淡出 |

场景不需要做满森林。先做“能藏身的灌木、能挡视线的岩石、能形成路线的路与围栏”，再用树和地表覆盖包装。

## 6. 全工种接口约定

- 世界尺寸统一按米描述；1个设计单位=1米。最终引擎可能使用厘米，导入时由程序统一换算。角色约1.65—1.75米，碰撞半径0.3米；主要道路宽≥2米，双人停留点宽≥2.5米。
- 模型脚底/底面为原点；朝向和坐标轴由程序在D1提供一个测试工程并锁定，D2前用1米方块和角色验证，禁止各人自行猜测。
- `CHR_`角色、`ENV_`场景、`PRP_`道具、`AN_`动画、`VFX_`特效、`UI_`界面、`SFX_`声音、`CP_`检查点、`E_`敌人。
- 示例：`CHR_A_Body_v01.fbx`、`AN_Common_CrouchMove_v01.fbx`、`UI_SK_A_FLUTE_v01.png`。版本号用于交付包，工程内稳定资源名由接入者维护。
- 3D交源文件、FBX、贴图和预览；2D交可编辑源文件和透明PNG；特效交目标引擎工程资源与录屏。引擎未定时先交贴图/序列帧与参数说明。
- 动画使用原地动作，由程序控制位移；特殊双人动作由程序对齐锚点。伤害、冷却和库存由游戏逻辑决定，动画/粒子结束不能决定敌人是否死亡。
- 资源状态统一为：待做→制作中→已交付→已接入→已验收。只有在游戏里通过对应条件才能写“已验收”。
- 每项P0先交可接入粗版，后交精修版；程序不等待精模开始实现。

## 7. D1需要锁定的决定

队长在开工会上填写：引擎及版本____；目标测试电脑____；程序负责人____；3D/动画负责人____；2D负责人____；特效负责人____；声音接入负责人____；Game Jam主题____。

这些空项不影响当前灰盒开工。默认先验证1920×1080、16:9和1280×720窗口；目标测试电脑上稳定60fps为目标，性能不足时先削减透明粒子、阴影距离和植物密度。目标设备未确定前不承诺性能达标。

若比赛主题后来公布，优先改任务文本、文书道具和场景叙事，不先改潜行底层系统。

## 8. 参考核对与本案改编边界

- 发行方介绍将友希定位为布陷阱并引开敌人的角色，将隼人定位为使用手里剑和忍刀的潜入者。本案保留这一互补方向。[发行方角色简介](https://cdn.uc.assets.prezly.com/d0e80427-0899-4826-9681-0282179acf73/-/inline/no/Shadow-Tactics_-Fact-Sheet.pdf)
- 社区机制指南描述了“石子使敌人转向落点、笛声让敌人前往调查”的区别，本案将其作为两种不同用途实现。[机制参考指南](https://steamcommunity.com/sharedfiles/filedetails/?id=1093176733)
- 本案的距离、时长、视野阈值、检查点、失败方式、统一拖尸、暂停规划均是为21天制作做出的设计选择，不是原作精确复刻。
- 用户指定的 typesafe-ai 技能已阅读，并核对其[实时文档索引](https://docs.typesafe.ai/llms.txt)与[构建指南](https://docs.typesafe.ai/concepts/how-to-build-with-system-one.md)。采用“确定性规则由程序负责”的原则。视野、听觉、巡逻、技能命中不接入联网模型；可选的制作期测试反馈分类见06，比赛原型无需TypeSafe账号或API。

以上为策划与制作说明，不包含已经完成的模型、动画、贴图或游戏程序。团队可立即用此包建任务、做灰盒和制作第一批资源。
