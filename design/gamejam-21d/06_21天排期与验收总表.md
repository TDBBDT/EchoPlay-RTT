# 21天排期、任务依赖与验收总表

版本v1.0。D1表示比赛制作的第一天，不预设具体日历日期。排期以00的默认团队条件为基础；成员可用时间未知，因此这是可执行的起始排期，不是完成时间保证。

## 1. 人力与容量

队长负责关卡灰盒、需求取舍、配置数值、每天集成、试玩组织和提交。不要把这些工作全部隐含分配给唯一程序。

| 方向 | 本案职责 | 起始投入估算 | 超量时先做什么 |
|---|---|---|---|
| 队长/关卡 | 文案、灰盒、调位、教学配置、试玩与资源验收 | 45—65小时 | 减少装饰与额外剧情，保持每天可玩 |
| 程序 | P0机制、UI接入、检查点、构建、修复 | 95—125小时 | 使用已有导航/UI系统、单敌类型、作者检查点；严禁新增通用框架 |
| 3D场景 | 19个基础网格或引擎替代件、共享材质、场景拼装 | 30—45小时 | 地形/道路用引擎，物件共享材质，变体靠旋转组合 |
| 角色/绑定/动画 | 两主角+一守卫、共用骨架、20条源动作 | 65—100小时 | 共用动作，使用已有可用基础动作并修正；先粗模 |
| 2D/UI | 两头像、5技能图标、状态/光标/面板、页面稿 | 25—40小时 | 通用框、程序遮罩、截图背景 |
| 特效 | 9项P0功能效果、接入、可选少量环境效果 | 20—35小时 | 一套声波材质派生，折射提供简化版 |
| 声音/接入 | 临时音挑选、事件绑定、音量平衡 | 6—10小时 | 先无配音，只保留关键反馈 |

这些是粗估，熟悉工具和已有资源会显著影响工时。若一个人同时承担场景、角色、动画，合计约95—145小时；若每天只有3小时，21天仅63小时，应在D1立刻采用共享人体基础网格和已有可用动作、保留低精风格，不能按完整精修量开工。

每人的计划只填可用时间的80%，剩余给接入、返修和比赛提交。所有工时包含本工种初步自检；最终集成还要保留D17—D21。

## 3. 五个不可跳过的里程碑

| 门槛 | 必须拿到的结果 | 没通过怎么办 |
|---|---|---|
| M1 / D3 | 可移动、可蹲、能躲视野、能失败重开 | 冻结所有美术扩展，程序只修闭环；队长减小灰盒 |
| M2 / D7 | 两角色有互补技能；陷阱/笛声与暗杀有效 | 暂停精修与P1；改用临时动作/几何模型，先解决技能结果 |
| M3 / D12 | A—F完整通关、四检查点、全部P0交互 | 取消所有P1；删除装饰和非必要路线，记录尚未完成P0 |
| M4 / D16 | 新手可独立完成；严重输入/重置问题已解 | 不再新增内容；只修解释不清、软锁和崩溃 |
| M5 / D20 | 构建包在干净机器完成一局 | 不改玩法，修运行依赖/资源路径/打包问题 |

P1启动条件：M3通过、没有阻断通关的缺陷、程序与对应美术都至少有2个完整制作日余量。两个P1中优先考虑同步规划；跳跃仅在已有成熟跳点实现或资源时做。都不做也满足本次原型目标。

若D12仍严重延期，队长应明确缩小版本定义并公布，而不是把缺失功能记作“已完成”。紧急减版顺序：所有P1/P2→环境装饰→E1独立教学段与飞镖整套→重复守卫与侧路。若删飞镖，必须同步删程序技能位、图标、教程、拾取道具与验收项，标注为v0.9减版；本v1.0默认仍包含飞镖。

## 6. 跨工种交付例子：吹笛

| 环节 | 负责人交什么 | 接收人检查什么 |
|---|---|---|
| 机制 | 程序：8米声源、6秒冷却、0.4秒生效、站立暴露 | 队长检查是否真的能诱敌及风险可解释 |
| 3D | 短竹笛模型、手持挂点、1.3秒动画 | 程序确认0.4秒时笛子已到嘴边 |
| 2D | 笛子图标、E键提示、冷却样式、“施放会站起” | 与3D道具造型一致，数值不写死在贴图 |
| 特效 | 8米双声波，接收Noise事件 | 实际半径一致，中心固定，不影响AI时机 |
| 声音 | 短笛声 | 发声与AI响应/特效同一事件 |
| 关卡 | E02在范围内，调查路径经过陷阱 | 试玩能看懂“先布置、再引来、后躲开” |

其他技能按同样方式验收。资源“做好了”不等于功能“能用了”。

## 7. 缺陷分级与每日会议

每日用10分钟确认三件事：昨天可玩包增加了什么；今天哪一项能交付并接入；谁被哪个具体资源/接口卡住。会议后队长更新任务状态与当天构建链接。

缺陷优先级：

1. 阻断：无法启动、崩溃、不能通关、角色永久卡住、检查点库存损坏。当日优先修。
2. 严重：视野判定与显示矛盾、听觉范围不一致、输入穿透、技能无反馈、教程软锁。暂停新功能修复。
3. 一般：滑步、偶发粒子穿插、文案溢出、路径绕行过远。进入最近一次修复批次。
4. 美化：更多落叶、复杂井架、额外立绘、材质微小细节。D16后默认不处理。

每天保留一个可运行构建，不只保留编辑器内场景。集成失败时回到上一可用包，单独定位新资源/功能。

## 9. typesafe-ai的可选使用位置

本原型不需要联网AI。若以后有大量自由文本试玩反馈，可在制作流程外用TypeSafe把反馈归类为“程序/关卡/视觉可读性/操作教学/其他”，再让队长复核；明确的构建编号、数值、日期和任务ID仍由程序或人工直接处理。

可选设计：输入包含测试者原话、所在关卡区、最近操作和游戏日志摘要；使用Choice选择一个最主要问题类别，允许“信息不足”；多个问题拆开分别判断。结果只用于整理，不自动改变游戏规则、不自动关闭缺陷、不把模型置信度当作问题真实性。

这项属于P2制作辅助，当前没有实现，也没有调用付费API。真正实施时再阅读当前SDK/API与对应问题类型文档、用实际反馈样本校验。D1—D21不为它预留开发时间。
