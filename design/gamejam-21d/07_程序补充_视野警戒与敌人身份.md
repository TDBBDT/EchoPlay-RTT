## 1. 核心整合：暴露值 ⇄ 黄色扇形扩散 [修订01 §4.1]

### 1.1 公式

沿用 01 的暴露值系统（近区 0.8/秒、远区 0.4/秒累积，不可见 0.6/秒衰减，每名敌人对每名玩家独立维护）：

```
黄色扇形半径 r      = exposure × R_far          // R_far = 10 米（01 的远区外径）
确认阈值 T(d)       = max(Floor, d / R_far)      // d = 该玩家到敌人的平面距离；Floor 默认 0.35
确认发现(Confirmed) :  当 exposure ≥ T(d) 时成立
```

等价的直觉描述：**黄色扇形从敌人眼睛里长出来，它扫到你的那一刻，就是被发现的那一刻。**

| 玩家距离 d | 所在区域 | 阈值 T(d) | 暴露累积速度 | 被确认所需时间 |
|---:|---|---:|---:|---:|
| 2 米 | 近区 | 0.35（触发 Floor） | 0.8/秒 | **0.44 秒** |
| 3 米 | 近区 | 0.35（触发 Floor） | 0.8/秒 | 0.44 秒 |
| 4 米 | 近区 | 0.40 | 0.8/秒 | 0.50 秒 |
| 5 米 | 近区 | 0.50 | 0.8/秒 | 0.63 秒 |
| 6 米 | 远区 | 0.60 | 0.4/秒 | 1.50 秒 |
| 8 米 | 远区 | 0.80 | 0.4/秒 | 2.00 秒 |
| 10 米 | 远区边缘 | 1.00 | 0.4/秒 | 2.50 秒（= 01 原定上限） |

设计意图：

- **近区（实线）"迅速触发警戒"**：0.44—0.63 秒，玩家基本来不及反应，符合"无论站立还是蹲下都会迅速触发"。
- **远区（虚线）站立**：1.5—2.5 秒，玩家有真实的补救窗口（蹲下、进灌木、退到岩石后），符合"虚线区站起来才会被发现"。
- **远区边缘仍是 2.5 秒**，与 01 §4.1 的原值完全一致，所以现有关卡在远距离上的节奏不会被破坏。
- `Floor=0.35` 是防止"贴到脸上 0.1 秒被抓"的硬地板；设 0 会让 2 米内几乎无法反应，设 1.0 就退回 01 的原始节奏（见 §14）。

### 1.2 与 01 旧规则的衔接（不需要改代码语义）

| 01 的说法 | 本文的等价表达 |
|---|---|
| 暴露值未满 1 属于"怀疑"，敌人缓慢朝最后可见位置转头，不放大视锥 | **黄色扇形正在扩散中**；敌人身体缓慢转向你的方向，黄色扇形随之扫过来 |
| 暴露值达到 1 → Confirmed | **黄色覆盖到你的身影** → 确认发现（红） |
| Confirmed 后连续可见 3 秒 → 任务失败 | 不变。**"被发现"到"任务失败"之间仍然是 3 秒**，这 3 秒就是玩家甩掉视线的最后机会 |
| 失去视线 → 前往最后已知位置搜索 | **黄色扇形回退**（0.6/秒衰减，视觉上是缩回去），敌人进入 Investigate / Search |

> 重要：01 里"暴露值到 1"和本文"黄色覆盖"是**同一件事的两种描述**。程序不要把两者写成两个判据，否则会出现"黄到人了但还没被发现"的矛盾。

## 2. 视野锥完整规格

### 2.1 形状与分区 [沿用01 §4]

- 视野扇形**总角 70°**（半角 35°），**近区 0—5 米**，**远区 5—10 米**。
- 术语对齐：**你说的"实线区域" = 01 的"近区"**（实填），**"虚线区域" = 01 的"远区"**（条纹）。程序变量建议用 `NearZone / FarZone`。
- 每名敌人每 0.1 秒更新一次感知；同一次更新内先读全部状态快照再统一应用（沿用 01，防顺序差异）。

```
              ╱│╲
           ╱   │   ╲
        ╱  近区(实填) ╲      0—5 米：蹲/站都可见（下蹲且不在灌木也算可见）
     ●────────┼────────●     5 米 分界
        ╲  远区(条纹) ╱      5—10 米：只有站立可见，下蹲不可见
           ╲   │   ╱
              ╲│╱
          敌人（扇形原点，朝上为中心线）
```

### 2.2 判定矩阵 [沿用01 §4.1，逐条对应你给的规则]

| 玩家状态 | 近区（实线） | 远区（虚线） | 对应规则 |
|---|---|---|---|
| 站立 / 行走 / 奔跑 | 可见 | 可见 | 站立时两区都会被察觉 |
| 下蹲且**不在**灌木 | **可见** | **不可见** | 近区蹲着也会被迅速警戒；虚线区蹲着安全 |
| 下蹲且**在**有效灌木内 | 不可见（贴脸例外） | 不可见 | 草丛里蹲着不会被发现 |
| 站立在灌木里 | 可见 | 可见 | 站起来就会被发现 |
| 站立施放飞镖 / 投石 / 吹笛 | 可见（即使原先下蹲） | 可见（即使在灌木中） | 沿用 01，施法必须起身 |
| 下蹲布陷阱 / 拖尸 | 按下蹲规则 | 按下蹲规则 | 沿用 01 |

补充规则（沿用 01，别漏）：

- 灌木判定以**角色中心进入 HideVolume** 为准，边界 0.15 米滞回，防隐藏状态抖动。
- **贴脸例外**：敌人距离隐藏玩家 ≤ **1.2 米**且无硬遮挡时可发现 → 草丛不是绝对无敌。
- 硬遮挡（石头、实墙、粗树干）有 `SightBlocker`；草、粒子、树叶**不阻挡射线**。
- P0 用躯干中心单点做遮挡射线；后续可扩为两点。

### 2.3 表现要求（与判定必须一致）

- 近区实填 + 远区条纹（05 §7 已定），遇硬遮挡裁剪扇形。
- 在裁剪显示完成前用 Debug 射线验证，**不允许拿完整扇形当最终表现**（01 §4 原文要求）。
- 绿色**不承担唯一安全提示**（00 §5）：安全信息由"近/远区 + 条纹 + 姿态图标"共同表达。

## 3. 黄色警戒扩散与结算 [新增]

### 3.1 触发与流程

```
玩家满足可见条件(§2.2)
        │
        ▼
[怀疑] exposure 开始累积 ──▶ 黄色扇形从扇形原点向外扩散（r = exposure × 10m）
        │                                    │
        │  可见条件中断                       │ 黄色半径 r ≥ 玩家距离 d
        ▼                                    ▼
   暴露值 0.6/秒衰减 ──▶ 黄色缩回          [确认发现 Confirmed·红]
        │                                    │
        └── 回到 0：恢复绿色                  │ 敌人转向玩家、3 米/秒追近、广播一次警报(10米)
                                             │
                                             ▼
                                连续可见 3 秒 → 任务失败（抓获）
                                             │
                                  失去视线 → 取消计时 → Investigate / Search
```

### 3.2 三条硬性约束

1. **扩散必须可中断**。黄色扇形是"确认进度"的可视化，不是不可逆的判定体。玩家在黄色扫到自己之前蹲下、钻进灌木、退出扇形或被岩石挡住 → 暴露值按 0.6/秒回退，黄色明显缩回，敌人退回怀疑/调查。
   > 如果扩散不可中断，"蹲在虚线区不会被发现"这条规则会在玩家已经蹲下之后依然被吃掉，玩家会认为规则骗人。
2. **黄到即确认，不叠加第二个判据**。覆盖瞬间 = Confirmed = 01 的"暴露值满"。此时才开始 3 秒抓获计时。
3. **表现与判定同源**。黄色扇形半径直接由暴露值驱动，不允许特效自己做一条"看起来更快"的曲线，否则玩家会按错误的距离感做决策。

### 3.3 状态色与头顶标记（与 05 §7 对齐）

| 阶段 | 视野锥 | 头顶标记（05 已有资源） | 敌人行为 |
|---|---|---|---|
| 未察觉 | 绿（近实填 / 远条纹） | 无 | 巡逻 / 站岗 / 对称扫描 |
| 怀疑（黄色扩散中） | 绿底 + 从原点扩散的**黄色扇形** | **问号**（UI_State_Set 已有） | 缓慢转向玩家方向，不放大视锥 |
| 调查（听到声音） | 绿 + 朝向声源的黄色定向扇形 | **耳朵**（刚听见）→ 问号 | 见 §5 |
| 确认发现 Confirmed | **红** | **叹号** | 转向玩家、3 米/秒追近、广播警报 |

> 不需要为黄色扩散新增美术资源：问号图标 + 黄色扇形材质即可表达。不要再叠一个"头顶进度环"，那会和扇形扩散重复表达同一件事，反而更难读。

### 3.4 边界处理

- 暂停时扩散冻结（玩法时间），与 04 §5 的时间规则一致。
- 检查点重试立刻清空暴露值、扩散半径与抓获计时（01 §9 已有要求，这里明确把"扩散半径"列入清理项）。
- 同一帧多个敌人同时扩散，各自独立；任一个覆盖即触发 Confirmed 与失败计时。
- 玩家在视野边缘反复进出时，加 0.1 秒滞回，避免黄色扇形抖动。

## 4. 扫描与朝向：idle 视野锥左右对称摆动 [新增]

### 4.1 两个角度必须分开命名，别混

| 参数 | 含义 | 默认值 |
|---|---|---:|
| `VisionHalfAngle` | 视野扇形半角（01 的 70° 总角） | 35° |
| `SweepHalfAngle` | 扫描幅度：中心线相对岗位朝向左右摆动的最大偏角 | 40° |
| `SweepSpeed` | 摆动角速度 | 20°/秒 |
| `SweepDwellTime` | 到达左右边界后的停留时间 | 1.2 秒 |

**摆动范围必须严格对称**：以岗位朝向 `IdleForward` 为 0°，最左 −40°、最右 +40°，不允许出现 −45°/+35° 这类偏移。守卫实际扫过的总角度 = 80° + 70° = 150°。

### 4.2 与 01 §6 状态机的衔接

- `Idle`（锚点停留）与 `Patrol` 的**点位停留 2—4 秒**期间：中心线按 §4.1 对称摆动，而不是死盯一个方向。
- `LookAt`（石子转头）：**不摆动**，固定朝向落点 2.5 秒后恢复原行为（沿用 01）。
- 例外（中等士兵）：`LookAt` 期间中心线偏移到声源方向后**以新中心线继续对称摆动**，观察时间结束后转回 `IdleForward`（见 §7.2）。
- `Investigate / Search`：01 规定 Search 是"原地按左/中/右固定节奏扫视，不随机游荡"——本文明确这三个节拍同样**对称**分布在当前位置朝向两侧。

### 4.3 验收方法

调试面板必须能实时显示每名敌人的 `IdleForward`、当前中心线角度、摆动边界角。验收时长时间观察，最左最右两个极值相对 `IdleForward` 的偏差应**完全相等**（±0.5° 容差）。

## 5. 声音：沿用 01 §5，只补四条

01 §5 的噪声表、优先级、抢占规则（相同优先级 0.75 秒内只接受一次）、"声波扩散只是表现、事件当帧即筛选敌人"全部**不变**。以下是补充：

1. **行走 / 蹲走不产生听觉事件**（01 §3 已定：P0 行走与下蹲移动无脚步听觉事件）。你说的"这两种状态的声音折射波都极小"，在本文里落成：**逻辑上没有噪声事件**，**表现上可以有极小的贴地波纹**（纯氛围，不参与 AI）。这样可以两者兼得，也不会让玩家误判守卫会听见。
   > 如果后期要让行走产生可被听见的噪声，需同时改 01 §3 的速度表、04 的声波参数和教学文案 TXT_Crouch。
2. **笛声对中等士兵与特殊敌人无效**（它们不离开岗位、不接受引诱）。因此笛声预览里的"小耳朵标记"必须只出现在**会响应**的敌人头上；对不受影响的敌人，悬停显示"该守卫不会离开岗位"。否则玩家会以为吹笛失败是 bug。
3. **新增一行噪声**：上房顶攀爬，半径 **2 米**，反应类型 = 移动调查（Investigate，疑惑）。加在 01 §5 表格里。
4. **特殊敌人不接收诱饵类事件**（石子、笛声、投掷物），连转头都不做；但仍接收**视觉类**刺激（看见尸体、看见玩家、目击暗杀）。

## 6. 玩家操作修订 [修订01 §2]

### 6.1 冲突点（必须先看清楚）

| 你的要求 | 01 §2 现状 | 冲突程度 |
|---|---|---|
| E / Q = 顺时针 / 逆时针转动方位 | Q/W/E = 三个技能槽 | **直接冲突** |
| 鼠标左键点击 = 移动目标点 | 左键 = 选人 / 确认技能；右键 = 移动 | **直接冲突** |
| 双击目标点 = 奔跑 | Shift+右键 = 奔跑 | 可并存，但教学文案要统一 |
| （未提） | 1 / 2 = 直接选人 | 若技能迁到数字键，则与 1/2 冲突 |

### 6.2 方案 A（推荐）：接受左键移动 + E/Q 旋转，技能迁到数字键

| 输入 | 行为 |
|---|---|
| **左键单击地面** | 移动到该点位；按当前姿态（站立 = 行走，下蹲 = 蹲走） |
| **左键双击地面** | 奔跑（双击窗口 ≤ 0.3 秒，两点间距 ≤ 0.5 米）；下蹲时立即起身再跑 |
| **左键单击角色 / 头像** | 选中该角色 |
| **右键地面 / 右键目标** | 情境交互（尸体、道具、文书箱）；瞄准中则取消瞄准，不产生移动 |
| **E / Q** | 顺时针 / 逆时针旋转镜头方位（步进 45°，插值 0.2 秒） |
| **1 / 2 / 3** | 当前选中角色的三个技能槽（原 Q/W/E，UI 角标同步改） |
| **Tab** | 在可用角色间切换（取代原 1/2 快捷选人） |
| **C** | 切换站立 / 下蹲 |
| **Shift + 左键 / Shift + 右键** | 奔跑（保留为等价备选，教学只教一种） |
| 其余（WASD 平移镜头、中键拖拽、滚轮缩放、F 归位、X 放下/取消、H 帮助、Esc、F8） | 全部沿用 01 |

代价与必须同步改的地方：

- 05 §2 HUD 示意图里的 `[Q 暗杀] [W 专属] [E 专属]` 改成 `[1] [2] [3]`，键帽角标改数字；`[1 苇音] [2 岚刃]` 改成 `[Tab 切换]`；

### 6.3 方案 B（备选）：保留 Q/W/E 技能，旋转改到 Z / X

优点是不动 UI、图标角标、教学文案与已冻结的键位约定；缺点是偏离"E/Q 旋转"的要求。**两方案都必须在 D1 前定死**，因为它同时牵动输入层、UI、教学、帮助页四处，中途改会造成连锁返修。

### 6.4 旋转镜头的规格（无论哪个方案）

- 旋转的是**镜头方位**，不是角色朝向；不改变技能方向、不改变玩家模型朝向。
- 步进 45°，播放 0.2 秒平滑插值；连续按可排队，不允许卡在中间角度。
- 旋转时**敌人视野锥的判定完全不受影响**（判定始终在世界坐标里），只是观看角度变化。这条要写进帮助页，避免玩家以为转头能把守卫"转晕"。
- 旋转后地面点击的落点要按"屏幕→世界"反算，验收用例见 T16。

### 6.5 双击奔跑的细节 [新增]

- 站立双击 → 直接奔跑（01 §3：4.2 米/秒，每 0.45 秒发一次 3 米噪声）。
- 下蹲双击 → **当帧起身为站立**，然后奔跑。起身即按站立参与视野判定（这是"立刻转变"的代价，必须让玩家感知到，靠声波与姿态图标表达）。
- 奔跑终点姿态：建议**保持站立**（新增参数 `RestoreStanceAfterRun=false`）；若队长希望贴回 01 的"临时奔跑"手感，把它设为 true 即可恢复原姿态。**[待确认]**
- 双击误触保护：UI 区域拦截双击；同一次双击必须落在同一片地面（不在角色身上、不在敌人身上）。

## 7. 三种敌人身份 [新增]

三种身份**共用 01 §6 的同一套状态机与同一套感知代码**，差异全部通过 `GuardConfig` 参数与能力开关表达，不新写三套 AI。

### 7.1 总表

| 维度 | ① 普通士兵 | ② 中等士兵 | ③ 特殊敌人 |
|---|---|---|---|
| 定位 | 01 的默认守卫，可被完整处理 | 固定哨位，只转头不离开岗位 | 不可对抗压力，只能绕 |
| 听到可疑噪声（奔跑/暗杀/飞镖/陷阱） | **Investigate**：寻路前往 + 进入警戒 | **只转头**：中心线对准声源后继续对称横扫 | **无反应** |
| 听到石子（诱饵） | **LookAt**：大幅转向落点 2.5 秒，不调查 | 同"只转头"，对准后继续横扫 | **无反应** |
| 听见笛声 | **Investigate**：前往声源 | 不前往 | 无反应 |
| 看见玩家 | 常规暴露累积 → Confirmed | 同左 | 同左（视野建议更强） |
| 看见尸体 / 目击暗杀 | 进入调查 / 直接 Confirmed | 同左（**建议**仍会移动处理，见 §14） | 同左 |
| 可被暗杀 / 陷阱 / 飞镖 | 是 | 是 | **否**（全部无效） |
| 视野参数 | 70° / 5 米 / 10 米（01 原值） | 同普通士兵 | **建议** 90° / 6 米 / 12 米 |
| 头顶标记 | 问号 / 叹号 / 耳朵 | 同上，可选"岗位锁定"小标 | 独立标识（不可处理） |
| 美术需求 | 已有（01/03 的守卫） | **需新增区分**（护肩 / 长枪 / 固定哨位姿态） | **需新增**（换色 + 装配件的最低成本方案） |

### 7.2 中等士兵的实现建议

不要新写状态，**参数化 01 已有的 `LookAt`**：

```
LookAt(中等士兵) : centerLine = 声源方向
                   while 观察中: 以 centerLine 为轴，按 SweepHalfAngle 对称摆动
                   观察时间到 → 按固定角速度插值转回 IdleForward，恢复原位扫描
```

新增字段：`lookAtSweep = true`、`lookAtHoldTime = 5 秒`、`homeForward = 岗位朝向`。

要点：

- 转动与转回都用**固定角速度插值**，不要瞬移；转回过程同样参与视野判定。
- 保存 `homeForward` 作为"家方位"，调查结束必须精确回到它（即 01 的 `Return` 状态语义）。
- 与 01 §5 的抢占规则并存：更高优先级刺激可以打断观察。

### 7.3 特殊敌人的实现建议与预留接口

- **继承中等士兵的全部行为**：一切声音只引发转身对准，不离开岗位。
- **引诱与干扰无效**：`IDistractable → false`，跳过全部诱饵类事件。
- **很难被杀死**：当前版本两位角色都无法处理；**不要做成"血量很高"**，直接走"不可处理"分支。
- 建议在 01 §12 的模块划分下新增能力接口：

```csharp
interface IDistractable    { bool CanBeDistracted { get; } }          // 普通 true / 中等 true(受限) / 特殊 false
interface ITakedownable    { bool CanBeTakedown(TakedownType t); }     // 普通 true / 中等 true / 特殊 false
interface IAuditoryResponse{ void OnNoise(NoiseEvent e); }             // 三种各自实现
```

预留理由：未来第三角色或关卡道具若需要对付特殊敌人，只需放行一个 `TakedownType` 并给特殊敌人开一条例外，不必改动 AI 主体。

### 7.4 技能对特殊敌人的逐条结果（必须写进 UI 文案）

| 技能 | 对特殊敌人的结果 | UI 表现 |
|---|---|---|
| SK_COMMON_KILL 近身暗杀 | 不可执行 | 悬停显示"该目标无法处理"；瞄准时不可确认 |
| SK_A_TRAP 陷阱 | 特殊敌人**不触发、不消耗**，机关保持 Armed，继续等下一名有效目标 | 预览圈内标出"该目标不会触发机关" |

| SK_B_STONE 石子 | 无反应 | 预览不给该敌人画受影响标记 |
| SK_A_FLUTE 笛声 | 无反应 | 预览不给该敌人画耳朵标记 |
| 拖尸 / 藏尸 | 不受影响（但特殊敌人可能目击） | 无 |

> 陷阱那一条必须实现，否则"只触发首名活敌人"的既有规则会被一名踩上去没事的特殊敌人白白吃掉，玩家会觉得机关坏了。

### 7.5 首关布置建议（对 02 §3 的修订建议）

02 现在写的是"7 名普通守卫"。建议改成 **5 普通 + 1 中等 + 1 特殊**：

## 8. 上房顶交互与优先级 [新增 / 触及 00 §3 范围]

### 8.1 定位：定点攀爬，不是自由攀爬

00 §3 把"自由跳跃/攀爬/钩锁"列在 P2，P1 只有"指定点跳跃"。**上房顶必须按同一思路实现**：关卡里成对配置的攀爬锚点（地面锚点 ↔ 房顶锚点），不允许自由攀爬，否则会同时引入寻路、碰撞、相机与关卡审核的连锁工作量。

建议执行口径：

- 锚点成对配置，间距与高差写死在关卡配置里（建议高度 ≤ 3 米）。
- 右键锚点 → 自动走到地面锚点 → 播放攀爬动作（建议 1.6 秒）→ 落到房顶锚点。
- 攀爬期间进入 01 §3 的**行动锁 `Acting`**：不接受移动、姿态与技能指令，可切人、可动镜头。

### 8.2 交互优先规则（你的核心要求）

| 优先级 | 系统 | 说明 |
|---:|---|---|
| 1 | 失败 / 胜利界面 | 沿用 01 |
| 2 | 暂停菜单 | 沿用 01 |
| **3** | **攀爬交互（Acting_Climb）** | **挂起"确认发现"判定**；敌人转为疑惑并走来 |
| 4 | 技能瞄准 | 沿用 01 |
| 5 | 情境交互 | 沿用 01 |
| 6 | 地面移动 | 沿用 01（方案 A 中为左键） |

攀爬期间的具体规则：

1. 该角色**不再累积暴露值**，不进入 Confirmed，不触发 3 秒抓获计时。
2. 但敌人会**转入疑惑**：头顶问号，朝攀爬锚点方向移动（Investigate），到达后按 01 的 Search 扫视 4 秒再 Return。
3. 攀爬完成、角色位于房顶后：按 §8.3 的高度规则处理。

### 8.3 房顶高度规则

- 为角色与敌人记录 `heightLevel`；高度差 > **2.5 米**时，地面敌人的视野锥**不检测**房顶角色（用高度遮蔽实现，可视为一种 `SightBlocker`）。
- 房顶角色**仍然遵守噪声规则**：在房顶奔跑会照常发出 3 米噪声，敌人会循声走到房下疑惑。
- 房顶不是永久安全区：建议房顶只提供**一条有限通路**（取物、绕开岗哨、抵达另一侧），玩家必须下来继续主线。
- 不做"房顶边缘露头/俯视"判定（复杂度高、收益低），但**禁止在房顶布置可被地面射线命中的检测点**，否则会出现"站在房顶上被下面的人看见"的矛盾。

### 8.4 漏洞防护（四条，必须实现）

1. **只对"怀疑/扩散中"生效**：已经被 Confirmed 的敌人不受攀爬保护影响——**已经被发现的人爬上去，落地后仍然会被追击**（抓获计时在攀爬结束后继续）。否则一次攀爬就能洗掉确认，规则会被玩坏。
2. **攀爬不可中途取消**：行动锁内不接受取消指令，防止玩家靠反复上/下房顶卡出无敌帧。
3. **攀爬本身产生 2 米噪声事件**（§5 新增行），所以"用攀爬躲视线"不是无代价的。
4. **锚点数量由关卡控制**（首关建议 1—2 处），不做任意位置可攀爬。

### 8.5 联动修改

- 00 §3 的冻结范围需要把"定点攀爬（上房顶）"从 P2 提到 P0/P1，并明确"自由攀爬仍然不做"。
- 03 需要一条攀爬动画（可两角色共用）；04 需要攀爬扬尘 + 一个交互反馈；05 需要教学文案与提示。
- 02 的 F 区或 E2 需要新增一处房顶路线，并写清房顶上能拿到什么、从哪里下来。

## 12. 排期与取舍建议 [对 06 的补充]

本文新增内容的粗略成本（沿用 06 的岗位口径）：

| 教学 / 检查点 / HUD 联动 | 1 日 | 0.5 日 | |
| **合计** | **6—8.5 日** | **4—5.5 日** | |

按 06 §1 的容量（程序 95—125 小时 ≈ 12—16 个 8 小时工作日）来看，**这 6—8.5 个程序日相当于额外吃掉一半余量**。建议取舍顺序：

1. **必做**：黄色扩散 + 阈值（本次要求核心）、输入方案改写（D1 前定死）、idle 对称扫描。
2. **优先做**：中等士兵（成本低、教学价值高、能让笛声出现"不管用"的场合）。
3. **二选一**：上房顶 **或** P1 规划模式。两者都是 2—3 日量级且都要动画与教学，21 天内同时做会挤掉 P0 回归时间。
4. **降级方案**：特殊敌人若工期不足，用"复用守卫模型换色 + 独特头顶标识 + 逻辑开关"实现，不做独立模型与动作，可压到 0.5 日。
5. **绝不能砍**：E_02 必须是普通士兵（笛声教学）、E_05 必须是普通士兵（飞镖教学）、E2 必须存在不接触特殊敌人的通关路线。
