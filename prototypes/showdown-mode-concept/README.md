# 决战时刻原型 — Showdown Mode Prototype

> **PROTOTYPE — NOT FOR PRODUCTION**
> 全部为丢弃型代码。绝不会被重构进正式项目。

**要验证的问题：** UE 5.6 能否实现赏金奇兵3 风格的决战时刻——暂停编排、帧精确按序执行、
且暂停期间世界真正完全冻结？

**日期：** 2026-09-19

---

## 运行步骤

1. 把 `showdown-mode-concept/` 整个文件夹复制到你的 UE 项目目录
2. 双击 `ShowdownProto.uproject`
   - UE 会提示"模块缺失，是否重新编译" → **是**
   - 首次编译约 1–3 分钟
3. 编辑器打开后：**File → New Level → Empty Level**
   - 不需要保存
   - 不需要摆任何 Actor —— GameMode 会在运行时生成全部场景
4. 按 **Play**

> **不需要**建蓝图、不需要连节点、不需要放 PlayerStart、不需要导入任何资产。
> 所有画面都是调试绘制（`DrawDebug*`），所以这个原型**零二进制资产依赖**。

### 若编译失败

把编译错误贴给我。Engine 路径原型通常需要 2–4 轮迭代才能跑起来，这是正常的。

## 操作

| 按键 | 功能 |
|------|------|
| **SPACE** | 冻结 / 解冻时间（解冻会丢弃未执行的指令） |
| **1 / 2** | 选择 1 号 / 2 号角色（蓝色 / 绿色） |
| **鼠标左键** | **冻结状态下**：点地面 = 排队移动；点敌人 = 排队击杀 |
| **E** | 执行所有排队指令（时间恢复） |
| **V** | 切换视野门控 —— **这是核心调试探针** |

## 画面元素

- **灰网格** — 地面（Z=0 平面）
- **蓝 / 绿圆柱** — 你的两个角色
- **红圆柱** — 敌人
- **绿色椎体** — 敌人视野锥
- **黄 / 红球体** — 排队的指令目标（沿路线的实心球是当前执行的）
- **白线** — 角色朝向

## 核心调试探针：V 键

这是整个原型最重要的部分，请务必两边都试一次。

**背景：** 暂停的实现方式是给所有单位设 `CustomTimeDilation = 0`。

**问题：** 这**只能**冻结读取 `DeltaTime` 的逻辑（移动、计时器、动画）。
敌人视野检测是纯点积/LOS 运算，不读 `DeltaTime`——所以它**根本不会被冻结**。

**怎么观察：**

1. 让 1 号角色走进敌人视野锥里
2. 按 **SPACE** 冻结
3. 看 HUD 的 `Detections while frozen` 一行

| V 键状态 | 预期现象 |
|----------|----------|
| **ON**（默认） | 计数保持 0。视野检测被显式跳过——正确行为 |
| **OFF** | 计数**继续增长**，视野锥变**品红**——原始 `CustomTimeDilation` 的真实行为 |

**结论：** `CustomTimeDilation = 0` **不足以**实现真正的世界冻结。
所有非 delta 驱动的逻辑都必须显式门控。这是要带回正式设计的技术结论。

## 代码结构

```
Source/ShowdownProto/
├── ProtoTypes.h              指令数据结构
├── ProtoUnit.h/.cpp          单位基类（手动移动 + 调试绘制）

├── ProtoEnemyUnit.h/.cpp     敌人（巡逻 + 视野锥 + 暂停门控）

```

### 已知的原型局限（这些是刻意的，不是 bug）

- **无寻路** — 单位直线移动，不绕障碍。正式版需要导航网格。
- **无动画** — 单位是圆柱体。**动画系统在时间膨胀下的行为未被本原型验证**，这是剩余风险。
- **无 AI Perception** — 视野是自己写的点积检测（更贴近 RTT 需要的确定性）。UE 原生
  `UAIPerceptionComponent` 在 `CustomTimeDilation = 0` 下的行为**未被验证**。
- **无角色技能差异** — 两个角色指令完全相同。
- **`CustomTimeDilation` 逐单位设置** — 正式版可能改用全局时间膨胀或引擎原生暂停，
  两者行为不同（引擎原生暂停会连 Tick 一起停，输入处理需要额外处理）。
